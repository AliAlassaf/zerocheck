# Evaluation on OTRF Security-Datasets

_Generated by `python evaluation/run.py`. Do not edit by hand._

**Data:** 14 recordings of real attack techniques from [OTRF Security-Datasets](https://github.com/OTRF/Security-Datasets) (Sysmon + Windows Security logs). Searched spans (where both Sysmon and Security have data) last 5s to 254s.

**Question:** `process_execution` — did the attack's process (for example `ntdsutil.exe`) run on the attacked host during the recording? Ground truth is the attack process, confirmed in each recording.

**Faults** (each one hides the evidence so a plain search returns zero results):

| Fault | What is injected | Expected reason |
|---|---|---|
| sensor_outage | Every event from the host dropped for 5s around the attack | `source_silent` |
| ingestion_lag | Everything from just before the attack onward not ingested yet | `ingestion_lag` |
| retention | Everything up to just after the attack already aged out | `retention` |
| parser_drift | `process.name` empty in process events from just before the attack onward | `field_missing` |
| logging_disabled | Sysmon EID 1 and Security 4688 not collected at all | `source_empty` |
| access_denied | The querying identity cannot read the Sysmon and Security indices | `no_access` |

**Baseline:** an analyst or agent who treats zero results as "didn't happen" accepts every one of these faulted searches as clean: 0% detected by construction.

**False warnings** are measured on the unmodified recordings: searching for a process that never ran (`mimikatz.exe`) must return `VERIFIED_NEGATIVE`. A warning whose blind intervals all fall inside a gap confirmed by hand in the original recording (listed under Datasets) is counted as a real gap instead.

## Results by silence threshold

`max_silence` is how long a host may send nothing on a channel before it counts as blind. Real deployments use minutes; these recordings are seconds long, so thresholds are scaled down to seconds.
